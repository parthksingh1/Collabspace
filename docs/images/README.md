## How these were captured

The app screenshots were taken with Playwright against `next dev`, with auth
seeded directly into `localStorage` (the same approach
`tests/e2e/playwright/multi-user-doc.spec.ts` uses) so the capture does not
depend on the login flow or a seeded database.

The Grafana screenshot is real data, not a mock:

1. Two ws-gateway nodes brought up via `tests/chaos/docker-compose.chaos.yml`.
2. Prometheus scraping both `/metrics` endpoints on a 5s interval.
3. Grafana with `infra/grafana/dashboards/collabspace.json` provisioned.
4. Six consecutive runs of the CRDT convergence integration suite against the
   cluster to generate genuine WebSocket, message and CRDT-update traffic.
5. Captured over a 20-minute window.

## What is deliberately not shown

The frame is cropped to the WebSocket and latency rows. The CRDT persistence
panels below them are fed by `collabspace_doc_*` metrics from doc-service, which
was not running in that rig, so they would have read "No data" — and a
screenshot of empty panels tells a reader nothing about the system. The panels
work; they simply had no source in this capture.

## Re-capturing

If the UI changes materially these will go stale. The app shots need only a dev
server and a Playwright script; the Grafana shot needs the five steps above.
Nothing here is generated by a committed script — these were one-off captures,
which is worth knowing before assuming they auto-update.
